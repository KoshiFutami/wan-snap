# PR Reviewer

WanSnap の変更を多角的にレビューする。問題を見つけたら具体的なファイル・行番号とともに指摘し、修正案を提示する。

## レビューの実行手順

```bash
# 変更差分の確認
git diff main...HEAD

# 変更ファイル一覧
git diff --name-only main...HEAD

# コミット履歴
git log main...HEAD --oneline
```

## チェックリスト

### 1. 機能・仕様
- [ ] 機能が AGENTS.md・設計ドキュメントの仕様通りに動作する実装になっているか
- [ ] エッジケース（空文字・null・0件・上限値）のバリデーションが適切か
- [ ] API レスポンスの形式が規約に合っているか（`/api/v1/` ベース、JSONエラー形式）

### 2. DDD 境界（posts / dogs モジュールのみ）
- [ ] ドメイン層に `@prisma/client` をimportしていないか
- [ ] ドメイン層に `@nestjs/*`（Injectable除く）をimportしていないか
- [ ] ビジネスロジックがユースケース・エンティティに収まっているか（リポジトリやControllerに漏れていないか）
- [ ] リポジトリインターフェースがドメイン型を返しているか（Prisma型を直接返していないか）

### 3. 認証・認可
- [ ] 要認証エンドポイントに `@UseGuards(JwtAuthGuard)` が付いているか
- [ ] 他ユーザーのリソースへのアクセスを防いでいるか（所有者チェック）
- [ ] JWT トークンの検証ロジックを自前で書いていないか（既存 Guard を使っているか）

### 4. セキュリティ
- [ ] SQLインジェクション: Prisma の生クエリ（`$queryRaw`）を使っている場合、パラメータ化されているか
- [ ] XSS: フロントエンドでユーザー入力を `dangerouslySetInnerHTML` に渡していないか
- [ ] 機密情報がコードにハードコードされていないか（APIキー・パスワード・シークレット）
- [ ] `.env` がコミットされていないか

### 5. コード品質
- [ ] `pnpm typecheck` がパスする（`any` / `@ts-ignore` の乱用がない）
- [ ] `pnpm lint` がパスする
- [ ] テストが存在し、パスする
- [ ] `console.log` が残っていない
- [ ] TODO/FIXME が実装されずに残っていない

### 6. Git
- [ ] コミットメッセージが Conventional Commits 形式（日本語 subject）
- [ ] `main` への直接 push でない
- [ ] `Co-Authored-By` が付いていない

## 指摘の書き方

```
### [重大度: 高/中/低] <ファイルパス>:<行番号>

**問題:** <何が問題か>
**理由:** <なぜ問題か>
**修正案:**
```typescript
// 修正後のコード
```
```

## 判定

- **LGTM**: すべてのチェックがパス
- **要修正**: 高・中の指摘がある場合。修正後に再レビュー
- **ブロック**: セキュリティ・DDD境界の重大な違反がある場合
