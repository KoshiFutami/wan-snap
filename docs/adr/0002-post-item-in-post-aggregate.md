# 0002. PostItem を Post 集約内に含める

- **ステータス:** Accepted
- **日付:** 2026-05-14

## 背景

着用アイテム（PostItem）は Post と同じテーブルグループで管理されるが、
DDDにおいては集約の境界をどこに引くかが設計上の重要な判断になる。

PostItem を Post の集約内に含めるか、独立した集約にするかを決める必要があった。

## 判断

PostItem は Post 集約内のエンティティとして扱い、`IPostRepository` 経由でのみ永続化する。
PostItem 単独を取得・更新するリポジトリは作らない。

## 理由

**Post 集約内に含める理由:**

- PostItem は Post なしに存在しない（Post が削除されると PostItem も消える）
- PostItem の操作は常に Post 経由で行われる（「この投稿のアイテムを更新する」）
- PostItem 単独で取得・検索するユースケースが現時点でない
- 集約を分けると、PostItem の更新時に Post との整合性チェックが複雑になる

**検討した代替案:**

- *独立集約にする:* PostItem を大量に扱う場合（例: 全投稿のアイテム横断検索）に有利だが、
  現在のユースケースでは過剰。将来その要件が生じた際に CQRS のリードモデルで対応する方が自然

## 結果

- Post を取得すれば PostItem も一緒に取れるため、N+1 クエリを避けやすい
- 1投稿あたりのアイテム数が極端に多くなった場合（数百件など）はメモリ上に展開するコストが上がる
  → 現実のユースケース（1投稿3〜5アイテム程度）では問題にならない想定
- PostItem を直接編集するユースケースが生じた場合、Post 集約ごと取得・更新する方針を維持する
