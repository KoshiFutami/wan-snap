# 0003. 一覧取得にカーソルページネーションを採用

- **ステータス:** Accepted
- **日付:** 2026-05-14

## 背景

スナップ一覧（GET /api/v1/posts）は無限スクロール型の UI を想定しており、
ページネーション方式を決める必要があった。

## 判断

カーソルページネーションを採用する。カーソルは `createdAt + id` の複合値（opaque string）とする。

## 理由

**カーソルページネーションを選んだ理由:**

- 新着投稿が随時追加されるフィードでは、オフセットページネーションで「ページ境界がずれる」問題が発生する
  （例: 2ページ目を取得する間に新投稿が追加されると、前ページの最後の投稿が2ページ目にも現れる）
- モバイルの無限スクロールとの相性が良い
- `createdAt` のみだと同一タイムスタンプが複数ある場合に結果が不安定になるため、`id` を補助キーとして使う

**検討した代替案:**

- *オフセットページネーション (`?page=2&limit=20`):* 実装が単純だが、リアルタイムフィードでのずれ問題がある
- *keyset ページネーション（`createdAt` のみ）:* カーソルより単純だが、タイムスタンプ衝突時に件数が前後する

## 結果

- クライアントは `nextCursor` を受け取り、次のリクエストに渡すだけでよい
- カーソルの中身（`createdAt + id`）はクライアントに公開しない（Base64 等でエンコード）
- 任意ページへのジャンプはできない（ユースケース上、フィード型では不要と判断）
- 総件数（`totalCount`）を返すコストを回避できる
