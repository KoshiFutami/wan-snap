# ブックマーク（スナップ保存）機能を実装する

## 概要

デザインファイルの複数の画面にブックマーク（スナップ保存）機能の UI が定義されているが、バックエンド・フロントエンドともに未実装。
現在 `/album` ページは「保存したスナップを見る機能は近日公開予定です。」というプレースホルダーのみ。
マイわん画面の「保存」タブも count=0 でプレースホルダー表示中。

## デザイン仕様（複数画面）

- **ホームフィード**（`screen-home.jsx` - FeedCard）:
  - フッターアクション行: ❤️ / 💬 / 📤 / **🔖 62**（ブックマーク件数）
- **投稿詳細画面**（`screen-detail.jsx` - DetailScreen）:
  - 右上フローティングヘッダー: 📤 シェア + **🔖 ブックマーク**（トグルボタン）
- **マイわん画面**（`screen-user.jsx` - MyProfileScreen）:
  - タブ: スナップ / アイテム / **保存 218**
  - 保存タブの中身: 自分が保存した投稿のグリッド表示
- **アルバム画面**（`screen-user.jsx` - AlbumScreen）:
  - 現在は「成長記録」アルバムとして設計されているが、BottomNav 4番目タブ「保存」との整合性を要確認

## 受け入れ条件

- [ ] `POST /api/v1/posts/:id/bookmark` — ブックマークする（認証必須）
- [ ] `DELETE /api/v1/posts/:id/bookmark` — ブックマーク解除
- [ ] `GET /api/v1/users/me/bookmarks` — 自分のブックマーク一覧
- [ ] 投稿詳細画面にブックマークトグルボタンを実装する（保存済み: 塗りつぶし表示）
- [ ] フィードカードにブックマーク件数を表示する
- [ ] マイわん画面「保存」タブに保存した投稿グリッドを表示する
- [ ] `/album` ページをデザイン通りに実装する（もしくは BottomNav 4番目タブを「お知らせ」に変更してアルバムを別ルートに移す）

## 技術メモ

- `bookmarks` テーブル: `user_id`（FK: users）/ `post_id`（FK: posts）/ `created_at`
- 複合ユニーク制約: `(user_id, post_id)`
- ブックマーク件数は `posts` テーブルに非正規化カウンタを持つか、都度集計
- BottomNav の4番目タブについては、デザインでは「お知らせ（Notifications）」。「保存」を BottomNav に残すかは設計判断が必要

## 関連デザインファイル

- `design/screen-home.jsx` — FeedCard（ブックマークアイコン + 件数）
- `design/screen-detail.jsx` — DetailScreen（ブックマークボタン）
- `design/screen-user.jsx` — MyProfileScreen（保存タブ）、AlbumScreen
- `design/shared.jsx` — TabBar（4番目タブ: `k="notifications"` がデザイン上の定義）
